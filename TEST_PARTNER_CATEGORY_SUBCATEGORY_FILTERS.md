# Gid Tourist — тест створення партнера: категорія, підкатегорія та фільтри

Охоплення: Адмінпанель → Партнери → Новий партнер; також редагування чинного партнера.

## Перевірки інтерфейсу
1. Відкрити форму «Новий партнер». Вибрати «Де поїсти». Під категорією має з'явитися список підкатегорій, що реально записаний у таблиці `categories`, наприклад «Українська кухня», «Неукраїнська кухня», «Фаст фуд», «Кавʼярні» за наявності в БД. Не має бути автоматичного «Ресторан».
2. Вибрати «Українська кухня». Вказати цінову категорію і, якщо вона дозволена конфігурацією, «Підходить для відвідування з дітьми».
3. Змінити категорію на «Де купити»: підкатегорія та несумісні параметри мають очиститися; варіанти підкатегорій оновитися. Повернутись до «Де поїсти» й знову вибрати підкатегорію.
4. Завершити створення тестового партнера з коректною адресою Geoapify та Telegram ID; перевірити, що збережений заклад з'явився у списку партнерів.
5. Відкрити його на редагування. Перевірити категорію, підкатегорію, ціну та чекбокси; зберегти ще раз без змін — значення не повинні зникати.
6. Змінити підкатегорію, зберегти та перевірити, що вона оновилась у каталозі туриста й у пошуку з фільтром за підкатегорією. Якщо заклад не опубліковано, каталог його не покаже.
7. Для категорії без туристичних підкатегорій форма бере типи з `place_type_templates`, якщо вони є (наприклад, «Готель» і «Садиба»). Якщо немає ані підкатегорій, ані шаблонів, вибір неактивний; створення без підкатегорії можливе.
8. Для ціни й ознак «з дітьми» переконатися, що пошук `/places?category=food&price_level=2&kids=true` повертає відповідний опублікований заклад у потрібному регіоні. Рейтинг, відстань і графік перевіряються автоматично — їх не можна призначати вручну.

## Лише читання, SQL перевірка Railway PostgreSQL
```sql
SELECT slug, name, subcategories, filter_config
FROM categories WHERE active = true ORDER BY sort_order;

SELECT id, name, category_slug, subcategory, price_level,
       attributes->>'kids' AS kids,
       attributes->>'parking' AS parking,
       status
FROM places
WHERE name ILIKE '%НАЗВА_ТЕСТОВОГО_ЗАКЛАДУ%'
ORDER BY created_at DESC LIMIT 10;
```

Зміни в PostgreSQL-схемі не потрібні: використовуються вже наявні `places.subcategory`, `places.price_level`, `places.attributes` і довідник `categories`.

Після заміни файлів потрібен деплой **Frontend і Backend**. Повний production-build та інтеграційні тести із живою базою слід виконати окремо перед передачею замовнику.
