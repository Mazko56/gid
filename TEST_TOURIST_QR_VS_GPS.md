# Gid Tourist — перевірка базової точки туриста (QR проти GPS)

Ціль: звичайний запуск використовує реальну GPS-позицію, запуск за QR — координати QR-локації. QR не підтверджує фізичну присутність, а тільки вибирає контекст каталогу і карти.

## Сценарій А. Звичайний запуск
1. Відкрийте Mini App через звичайну кнопку бота без `startapp` або іншого QR-параметра.
2. Дозвольте геолокацію Telegram або браузеру.
3. Перевірте, що головна показує назву населеного пункту з `GET /geo/reverse?lat=...&lng=...` (Geoapify), а не шаблонний Татарів.
4. Відкрийте «Де поїсти» та «Що поруч». Перевірте, що карта центрована за GPS і каталог показує схвалені заклади в обраному радіусі, навіть якщо немає QR-контексту.
5. Перейдіть в експрес- та розширений планувальники: географічною точкою старту має бути GPS. Для перевірки backend використовуйте `gps_lat`, `gps_lng` у генерації.
6. Вимкніть геолокацію й повторіть запуск. Додаток не повинен показувати довільне місто чи підміняти GPS Татаровом. Мапа просить доступ; у планувальнику доступний вибір міста вручну.

## Сценарій Б. QR конкретного закладу
1. Візьміть активний QR закладу «Готель А» з коректними `place_id` і координатами в БД.
2. Відкрийте QR на пристрої, чия GPS-позиція знаходиться в іншій частині міста або взагалі в іншому місті.
3. Привітання має показувати **назву «Готель А»**, а не GPS-місто чи шаблонну назву регіону.
4. «Де поїсти», «Що поруч», карта й планувальник повинні використовувати координати **«Готелю А»**, а не GPS-пристрою.
5. Перезапустіть Mini App з тим самим QR. Контекст не повинен змінюватися від раніше наданого дозволу на GPS.
6. Для QR загальної регіональної точки без `place_id` перевірте, що базовими будуть координати центру регіону з QR.

## Безпека, обмеження та практична перевірка
- Створення/підтвердження фінансової операції як і раніше перевіряється на сервері; зміни пошукової точки не є підтвердженням фізичної присутності.
- Фактичне місто при звичайному запуску можна назвати тільки після успішного визначення координат і зворотного геокодування. Якщо Geoapify недоступний, відображаються координати, а не вигадана назва.
- Для GPS-пошуку необхідні схвалені заклади з координатами в PostgreSQL. Показ обмежений радіусом користувача; запис далеко від базової точки не повинен з'являтися в «Що поруч».
- Перевірте обидві мови EN/PL після перемикання, а також відсутність зміни оригінальної верстки.

## Локальні перевірки
```
node test_tourist_launch_origin.cjs
node test_planner_engine.cjs
npm ci
npx tsc --noEmit --pretty false
npm run build
cd backend && npm ci && npm run build
```

Після деплою повторіть два сценарії у Telegram Android та iOS із реальною PostgreSQL та ключем `GEOAPIFY_API_KEY`.
