# Gid Tourist — перевірка виправлень від 15.11.2026

## Що змінено
1. Створення/редагування партнера: Geoapify autocomplete робить запити тільки після фокусування відповідного поля. Редагування не відкриває всі підказки автоматично. Після вибору підказки поле втрачає режим пошуку.
2. Категорії закладу: зберігаються **кілька підкатегорій основного каталогу** і **кілька типів на мапі «Що поруч»**. Списки 8 розділів/64 фільтри взято дослівно з існуючого `NearbyScreen`, змін до туристичних назв фільтрів не вносили. Зберігання — у `places.details.admin_category_subcategories`, `places.details.admin_nearby_filters` і існуючій таблиці `place_tags`. Після зміни категорії вибори очищуються. Під час редагування старі значення не губляться, навіть якщо їх уже прибрали з довідника.
3. «Мої плани»: новий пункт у профілі, окремий список із переходом до збережених маршрутів; зі стартового екрану планувальника старий блок видалено.
4. Планувальник: вибір компанії задає лічильники (самостійно 1+0, пара 2+0, сім’я 2+1, друзі 3+0, компанія 5+0). Для поточної дати найраніший час — найближчі майбутні 5 хвилин. Перевірка типів відпочинку виконується на кроці вибору; висота бюджетних кнопок зменшена до 42px, дизайн не замінено.
5. Пошук: сервер знаходить за назвою, адресою, описом, категорією та призначеними ознаками; координати й радіус мають пріоритет над адміністративним `region_id` QR. Для туристичних каталогу/мапи/трансферу прибрано повторне одночасне завантаження, stale результати не показуються при іншому пошуковому запиті.

## Railway / deployment
- Змінити Frontend та Backend одночасно (обидва містять новий код).
- **Нових міграцій БД не потрібно** (`place_tags` та JSONB `details` уже існували).
- Перевірити `GEOAPIFY_API_KEY`, `GEO_ADDRESS_SIGNING_SECRET` у Backend; не показувати їх у логах чи комітах.
- У цьому середовищі немає повного набору npm-залежностей. Перевірки синтаксису та модельних сценаріїв пройшли; production-build та перевірка на реальній БД мають пройти в Railway.

## Перевірка вручну
1. В адмінці редагувати наявний заклад із заповненими містом/вулицею/будинком. Після відкриття НЕ повинно бути автосписків. У Network не повинно бути `/geo/autocomplete`, доки не натиснути на відповідне поле. Натиснути на місто, змінити текст — має з’явитися лише список міст.
2. Для тестового закладу «Де поїсти» поставити дві підкатегорії (наприклад «Українська кухня» та «Фаст фуд») й два типи мапи («Ресторани», «Кафе»). Зберегти та знову відкрити редагування — всі чотири мають бути позначені.
3. Опублікувати тестовий заклад, відкрити QR з іншого району міста, задати радіус, який включає заклад. У «Що поруч» перевірити по черзі «Ресторани» і «Кафе»; обидва мають знаходити ту саму картку. У «Де поїсти» перевірити обидві підкатегорії. У пошуку ввести назву та частину адреси.
4. У профілі натиснути «Мої плани», перевірити порожній стан. Створити маршрут, зберегти, повернутися у профіль — маршрут має з’явитися в списку й відкриватися з нього.
5. У планувальнику натиснути «Сам / сама» -> 1 дорослий; «Сім’я з дітьми» -> 2 дорослих та 1 дитина; далі числа можна змінювати вручну. На сьогодні не можна обрати час раніше за поточний. Без жодного вибраного виду відпочинку кнопка «Далі» має показати помилку на кроці з інтересами, не в підсумку.
6. Перевірити фільтрацію за «з дітьми», паркуванням, рівнем ціни і радіусом. Категорію/підкатегорію не повинно скидати, якщо повторно завантажити сторінку редагування.

## Безпечні read-only SQL перевірки
```sql
SELECT p.id, p.name, p.category_slug, p.subcategory, p.status,
       p.details->'admin_category_subcategories' AS main_subcategories,
       p.details->'admin_nearby_filters' AS nearby_filters
FROM places p
WHERE p.name ILIKE '%НАЗВА_ТЕСТОВОГО_ЗАКЛАДУ%';

SELECT p.name, t.tag
FROM places p
JOIN place_tags t ON t.place_id = p.id
WHERE p.name ILIKE '%НАЗВА_ТЕСТОВОГО_ЗАКЛАДУ%'
ORDER BY p.name, t.tag;

SELECT id, title, region_id, updated_at
FROM trip_plans
ORDER BY updated_at DESC
LIMIT 20;
```
**Примітка:** `trip_plans` уже визначено у схемі `backend/src/database/schema.ts`. Якщо deployment використовує старішу схему, спершу перевірити статус міграцій.
