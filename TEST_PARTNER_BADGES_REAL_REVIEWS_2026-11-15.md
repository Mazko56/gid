# Gid Tourist — позначки закладів та реальні відгуки

## Що змінено

- Адмінпанель → Партнери → Новий партнер / Редагувати партнера: окремий компактний набір незалежних позначок «Партнер», «Реклама», «Ми рекомендуємо». Можна вибрати 0–3 позначки. Збереження у `places.attributes.display_badges` (JSONB), без міграції.
- Backend перевіряє дозволені коди (`partner`, `advertisement`, `recommended`); партнерський кабінет не може самостійно додати рекламні або редакційні позначки чи стерти їх при редагуванні. Факт партнерства (`attributes.partner`) не залежить від показу позначки. Старі партнери без нового поля продовжують показувати «Партнер».
- Позначки показуються в каталозі, у списку та попередньому перегляді мапи «Що поруч», а також у картці закладу; наявні фільтри й категорії не змінені.
- Для закладів PostgreSQL блок відгуків у картці працює через `GET /reviews/place/:id`, а не через Google. API показує лише `review_entries.status='approved'` для опублікованих закладів. Відображаються автор, реальний рейтинг, текст, дата, відповідь партнера, якщо вона є.
- При відсутності схвалених відгуків відкривається порожній стан. Ніяких вигаданих відгуків.
- Зовнішні локації (якщо їх окремо увімкнуть знову) не мають локального `place_id` і можуть показати лише ті відгуки, які дійсно надані зовнішнім провайдером. Вони не підставляються до наших локальних закладів.

## Ручна перевірка в Railway та Telegram

1. Після деплою Frontend і Backend: Адмінпанель → Партнери → Створення партнера. Вибрати «Реклама» та «Ми рекомендуємо», зняти «Партнер», зберегти/опублікувати. Відкрити заклад у туристичному каталозі, а також у «Що поруч»: повинні бути рівно ці дві позначки.
2. Знову відкрити цього партнера на редагування. Значення мають відновитися. Змінити лише позначки, натиснути «Зберегти зміни», повторити перегляд.
3. Перевірити старого партнера без поля `display_badges` — відображається початкова позначка «Партнер».
4. На картці партнера натиснути блок рейтингу/відгуків. Список відкривається в застосунку; напис «Google» більше не додається до лічильника чи заголовка. Якщо відгуків немає — порожній стан, а не шаблонний запис.
5. Залишити відгук після підтвердженої покупки або завершеного бронювання. До схвалення адміністрацією він не має бути публічним. Після модерації «Схвалено» — відкриття списку має показувати автора, оцінку, текст і дату. При відповіді партнера — також відповідь.

## Безпечні SQL-запити для перевірки (тільки SELECT)

```sql
-- Перевірити позначки, не розкриваючи приватні контакти
SELECT id, name, status, attributes->'display_badges' AS display_badges,
       attributes->>'partner' AS partner
FROM places
WHERE organization_id IS NOT NULL
ORDER BY updated_at DESC LIMIT 30;

-- Схвалені відгуки з реальними авторами (замінити ID закладу)
SELECT r.id, r.place_id, u.first_name AS author, r.rating, r.text,
       r.partner_reply, r.status, r.created_at
FROM review_entries r JOIN users u ON u.id=r.user_id
WHERE r.place_id = 'ВСТАВИТИ_PLACE_ID'
ORDER BY r.created_at DESC LIMIT 100;

-- Звірити публічний лічильник тільки за схваленими
SELECT p.id, p.name, p.review_count, COUNT(r.id) AS approved_reviews
FROM places p LEFT JOIN review_entries r
  ON r.place_id=p.id AND r.status='approved'
WHERE p.id='ВСТАВИТИ_PLACE_ID'
GROUP BY p.id, p.name, p.review_count;
```
