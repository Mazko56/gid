# Гід туриста — зміни за документом «Правки гід» (19.10.2026)

Це **повний архів проєкту** на основі `gid1710_RAILWAY_BUILD_FIXED.zip`. Збережено файли та каталоги `app/`, `backend/`, `bot/`, `public/`, конфігурацію та медіафайли. Зміни локальні до коду, таблиці PostgreSQL із реальними даними не видаляються.

## Реалізовано

1. **Адреса в адмінці:** місто/село, вулиця і будинок підбираються за введеним текстом. Збережено вибір точки на мапі. Текстові помилки API тепер показуються користувачу, а не маскуються порожнім списком. Вулицю й будинок дозволено вводити після заповнення попередніх полів як в адмінці, так і в мобільній формі партнера, але **публікація все одно потребує перевіреної адреси** з підказок або точки на мапі.
2. **Геосервіс для адрес:** backend використовує Google Places, якщо ключ налаштований; у разі відсутності/помилки Google переключається на Geoapify (якщо налаштований `GEOAPIFY_API_KEY`). Geoapify-підказки підписуються сервером, мають обмежений час дії, їх не можна підмінити даними з браузера. Це **пошук адрес**, не сторонніх закладів.
3. **Каталог та мапа:** туристичний API `/places` уже повертав лише схвалені локації з PostgreSQL; цей механізм залишено. Мапа використовує Leaflet/OSM для картографічного тла та маркери лише зі схвалених об'єктів платформи. Google Places/Geoapify не додають сторонні заклади у звичайний каталог. Гарячі пропозиції створюються в системі й проходять передбачену фільтрацію.
4. **Справжні клієнти, бонуси, статистика та взаєморозрахунки:** нові API адміністрування отримують користувачів, транзакції, агрегати та журнал бонусів із PostgreSQL. Демонстраційні імена, чеки 2024 року, криві, баланси та псевдографіки на відповідних екранах замінено показниками з бази. Картки клієнта та історія партнера також використовують дані API. Баланси й обороти рахуються за повною історією SQL, а не лише за останніми ста записами. За відсутності подій показуються порожні стани/нули. **Не підмінюємо комісію фактично сплаченими рахунками:** інтеграції бухгалтерських оплат у проєкті немає.
5. **QR-сканування:** залишено існуючу камеру й візуальну рамку всередині Telegram Mini App, зелена смуга анімована. QR читається автоматично через браузерний BarcodeDetector; у WebView без нього використовується резервний jsQR через зовнішній CDN. Окрему кнопку відкриття Telegram scan popup прибрано. Передбачено ручне введення коду як аварійний варіант.
6. **Запуск Railway Frontend:** для Next.js Standalone `server.js` створено `commonjs` package scope в *runner* образі; це усуває можливий конфлікт `"type": "module"` кореневого пакета з CommonJS standalone сервером. Healthcheck `/api/health`, порт `3000`, bind `0.0.0.0` залишені.

## Railway — потрібні змінні

### backend
- `DATABASE_URL=${{Postgres.DATABASE_URL}}`
- `ADMIN_API_KEY` — випадковий секрет, щонайменше 16 символів.
- `GEO_ADDRESS_SIGNING_SECRET` — окремий стабільний секрет щонайменше 16 символів. **Не змінювати між деплоями без потреби** (вже вибрані адреси в браузерах доведеться обрати повторно).
- **Принаймні один** геоключ: `GOOGLE_MAPS_SERVER_API_KEY` (Google Places API New + Billing) **або** `GEOAPIFY_API_KEY` (Geoapify Geocoding Autocomplete). Для резервного провайдера краще налаштувати обидва.
- `TELEGRAM_BOT_TOKEN` та решта наявних backend-змінних з попереднього README.

### frontend
- `PORT=3000`, `HOSTNAME=0.0.0.0`, `NODE_ENV=production`.
- `BACKEND_API_URL=http://backend.railway.internal:3000` (якщо Railway-сервіс справді має ім'я `backend`).
- `STAGE2_ADMIN_API_KEY` має збігатися з backend `ADMIN_API_KEY`.
- Healthcheck Path: `/api/health`.

## Важливі обмеження перевірки

- Структуру TypeScript/TSX (43 файли) перевірено компіляторним parser API: синтаксичних помилок немає. **Повний `npm run build` неможливо завершити в ізольованому середовищі**: npm registry недоступний, залежності не встановилися повністю. Тому після пушу треба перевірити Railway Build та Deploy Logs.
- Live-тести з PostgreSQL, Telegram WebView (зокрема iOS), Google/Geoapify keys та камерою не виконувались. Резервний jsQR вимагає доступу клієнтського WebView до `cdn.jsdelivr.net`; за недоступності CDN залишиться ручний ввід. Жодну роботу сканера на iPhone без реального пристрою не слід вважати підтвердженою.
- Загальний інтерфейс, зображення, маршрути, ролі та інші модулі не переписувалися. Наявні дані PostgreSQL зберігаються: програмні правки не видаляють замовлення, фото, бронювання чи бонусні записи.
