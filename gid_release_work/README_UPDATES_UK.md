# «Гід туриста» — зміни в архіві (17.10.2026)

Це **повний архів вихідного проєкту** із внесеними доробками. Існуючі стилі, компоненти та навігаційну концепцію збережено. Файл не є підтвердженням завершення всіх вимог 18-сторінкового ТЗ на рівні промислової експлуатації.

## Що додано

- У backend — таблиці ресурсів, бронювань, одноразових QR, транзакцій, незмінних записів бонусного журналу, відгуків, планів, заявок готелю, амбасадорів та аудиту.
- Фінансові API: короткочасний QR клієнта, перевірка QR персоналом закладу, розрахунок покупки, підтвердження клієнтом, відхилення, повернення, історія транзакцій і бонусного гаманця. Використовуються транзакції БД, блокування та ключі ідемпотентності.
- Ресурсні бронювання: доступність, створення заявки, додавання записів партнером, зміна статусів, захист від дублювання зайнятих слотів.
- Відгуки за підтвердженою взаємодією, відповіді партнера, модерація; заявки гостей готелю; збереження планів; базова реєстрація й атрибуція амбасадорів.
- В інтерфейсі туриста: підключення кошика бонусів/історії, динамічного QR із таймером, підтвердження покупки, ресурсного бронювання, перевірки права на відгук, запиту експорту/видалення облікового запису.
- В інтерфейсі партнера: QR-сканування (коли підтримується камерою/Telegram) з резервним введенням, запуск операції, керування ресурсами та бронюваннями.
- Захищено frontend-проксі адміністративного API від анонімних викликів; доступ до адміністративних операцій вимагає належного ключа або перевіреної адміністративної сесії.
- QR зображується локально через включену бібліотеку з ліцензією, без відправки фінансового QR на сторонні QR-сервіси.

## Запуск

Рекомендовано Node.js >=22.13, PostgreSQL і змінні середовища з `.env.example` та backend-конфігурації. В корені:

```bash
npm ci
npm run build
npm run start
```

У `backend/`:

```bash
npm ci
npm run build
npm run start
```

До запуску потрібно заповнити DB/Telegram/API/адміністративні секрети, налаштувати міграцію схеми та публічний HTTPS-домен Mini App. Адміністративний секрет необхідно зберігати виключно в серверних env, не публікувати у фронтенді.

## Межі готовності та перевірки

- **Не заявляється повна відповідність 1:1 всім пунктам ТЗ**: у вихідному архіві були демонстраційні екрани. Частина регіональної адмінки, інтерфейсів амбасадора, сценаріїв/планувальника, карти, локалізацій, партнерських звітів і готельних сервісів потребує окремого підключення до API та end-to-end перевірки.
- Потрібні повне тестування tenant/RBAC, 2FA, автоматичні завдання expiry/розсилок, політики retention, production Redis/queue/S3, юридичні умови бонусів і взаєморозрахунків, погодозалежність, часові пояси/DST та перевірки навантаження.
- Синтаксис TS/TSX і код Telegram-бота перевірено, локальний QR-код успішно декодується. **Повну збірку та інтеграційні сценарії з реальною PostgreSQL/Telegram не вдалося виконати в цьому середовищі**, тому перед продакшн-деплоєм обов'язково виконайте `npm ci`, `npm run build`, тести та перевірку фінансових сценаріїв на staging.

## Важливо

Не проводьте справжні фінансові розрахунки або нарахування бонусів без повного тестування, незалежного security review, погодженої юридичної моделі та перевірки атомарності й бухгалтерських записів на реальній БД.
